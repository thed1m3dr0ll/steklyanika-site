# Как найти нужное в коде за 10 секунд

Инструкция для вас, для стажёра и для меня. Основа — навигационные карты в начале каждого файла.

---

## 1. Открыли файл — сразу видите карту

В начале каждого из **73 файлов** стоит шапка: что за файл, сколько строк и где какие блоки.

Пример — `src/pages/about.astro`:

```
//  СТРАНИЦА          about.astro · 522 строк
//
//  КАРТА ФАЙЛА — блоки и строки:
//
//   1  НАЧАЛО ДАННЫХ  импорты, константы, типы
//  81  КОНЕЦ ДАННЫХ   константы из шапки уходят в разметку
//  93  СЕКЦИЯ         section section--white history
// 109  СЕКЦИЯ         timeline
// 158  СЕКЦИЯ         section section--white today
// 176  СТИЛИ          начало <style>
// 299  СКРИПТ         клиентский JS
//
//  Тексты этапов развития — массив `timeline` в блоке данных.
//  Внешний вид ленты — стили «Таймлайн» и объект `ribbon`.
```

Дальше не надо листать: видно, что текст истории компании на строке 93, а лента — на 109.

## 2. Ищете по типу блока, а не по всему проекту

В шапке всегда один из типов:

| Тип | Что это | Где встречается |
|---|---|---|
| `СТРАНИЦА` | готовый URL сайта | `src/pages/**` |
| `КОМПОНЕНТ` | кусок разметки с пропсами | `src/components/**` |
| `МАКЕТ` | общий каркас с `<head>` | `src/layouts/` |
| `ДАННЫЕ` | тексты и цифры без разметки | `src/data/**` |
| `КЛИЕНТСКИЙ СКРИПТ` | JS в браузере | `src/scripts/**` |
| `ФАЙЛ` | стили | `src/styles/` |

Менять текст — идёте в `ДАННЫЕ`. Менять вид — в `СТИЛИ` того же файла. Менять поведение — в `СКРИПТ`.

## 4. Инструмент: карта любого файла по требованию

```bash
cd site
node tools/карта-файла.mjs src/components/Header.astro
```

Напечатает точные номера строк всех секций, стилей, функций.

Сразу по нескольким:

```bash
node tools/карта-файла.mjs $(find src -name '*.astro')
```

## 5. Инструмент: разложить новые файлы по блокам

Если добавили файл и хотите такую же шапку:

```bash
cd site
node tools/разложить-по-блокам.mjs              # посмотреть, что сделает
node tools/разложить-по-блокам.mjs --write      # применить
node tools/разложить-по-блокам.mjs src/pages/new.astro --write   # только один файл
```

Скрипт **не трогает разметку**, только вставляет комментарий с картой. Уже разложенные файлы пропускает.

## 6. Проверка, что ничего не сломалось

Перед любым коммитом:

```bash
cd site
npx tsc --noEmit      # типы
npm run build         # сборка, должно быть 32 page(s) built
```

Если правили только комментарии, разметка обязана остаться прежней. Проверить так:

```bash
# до правок
cp -r dist /tmp/baseline

# после правок и сборки
diff -r /tmp/baseline dist
```

Пусто — значит байт в байт, ничего не поехало.

## 7. Ловушки, на которые я уже наступил

Записано, чтобы стажёр не повторил:

**1. Два `---` в .astro.** Первый открывает блок данных, второй закрывает. Скрипт, который
режет «первые три символа», примет закрывающий за открывающий и вставит код в разметку.
Сборка упадёт с `Expected } but found :`. Правильно — работать по номерам строк.

**2. `//` в CSS.** Не комментарий, а мусор. Стили поедут. В CSS только `/* */`.

**3. Сборка «висит» на ровном месте.** Если параллельно работает `npm run dev`, он держит
300+ МБ. На машине с 2 ГБ сборке не хватает памяти, и она падает молча, не оставляя HTML.
Лечится просто: остановить dev перед сборкой.

**4. astro dev после сборки.** `astro dev` пишет в `.astro/`, сборка тоже. Не запускать оба сразу.

## 8. Что осталось не разложенным

Каталоги `src/assets`, `src/content/objects`, `public/admin/decap` — это картинки и готовые
библиотеки, а не код. Их разбирать нечего.
