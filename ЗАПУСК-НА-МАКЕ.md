## 2. Проверить Node

```bash
node -v
```

Нужно **v22.12 или новее**. Если меньше:

```bash
ARCH=$(uname -m); [ "$ARCH" = "x86_64" ] && A=x64 || A=arm64
VER=22.20.0
curl -fL -o /tmp/node.tar.gz "https://nodejs.org/dist/v$VER/node-v$VER-darwin-$A.tar.gz"
mkdir -p ~/.local/node22 && tar -xzf /tmp/node.tar.gz -C ~/.local/node22 --strip-components=1
echo 'export PATH="$HOME/.local/node22/bin:$PATH"' >> ~/.bash_profile
export PATH="$HOME/.local/node22/bin:$PATH"
node -v
```

## 3. Запустить

Двойной клик по **`Запустить всё.command`** в папке проекта.

Из терминала имя берётся в кавычки — `./"Запустить всё.command"`. Пробел в имени bash считает
разделителем и ищет файл `./Запустить`, отсюда `No such file or directory` при живом файле.

Если Finder говорит «нет прав на исполнение» — один раз в терминале:

```bash
cd "/Users/skatinov/Downloads/Сайт Стекляника 17"
chmod +x "Запустить всё.command"
```

Скрипт сам: создаст `.env` со случайной солью, поставит зависимости, заведёт трёх пользователей,
зальёт демо-данные, поднимет сервер заявок и сайт.

Откроется в браузере:

| Что | Адрес |
|---|---|
| Сайт | http://localhost:4321 |
| Кабинет | http://localhost:4321/admin/cabinet/ |

**Вход (демо, поменять перед боевым запуском):**

| Роль | Логин | Пароль |
|---|---|---|
| Админ | `boss@steklyanika.ru` | `admin-pass-2026!` |
| HR | `hr@steklyanika.ru` | `hr-pass-2026!` |
| Маркетинг | `mkt@steklyanika.ru` | `mkt-pass-2026!` |

Остановить: `Ctrl+C` в окне терминала. Сервер заявок погасится сам.

## 4. Что посмотреть в первую очередь

1. **Кабинет, панель «Заявки»** — там 6 демо-заявок с разными статусами. Проверь фильтры и поиск.
2. **Панель «Тексты»** — четыре записи, у двух статус «черновик», у двух «опубликован».
3. **Панель «Медиа»** — загрузи фото. Подпись (alt) обязательна, без неё не пустит.
4. **Панель «Статистика»** — пока заглушка: нет токена Метрики. Нажми «Обновить», увидишь ответ сервера.
5. **Форма заявки на сайте** — отправь и проверь, что она появилась в кабинете у HR.

## 5. Если что-то не так

**«Порт 4321 занят»** — значит уже запущено. `astro dev stop` или закрой старое окно терминала.

**«Сервер не отвечает» в кабинете** — не поднялся API. Проверь:
```bash
curl localhost:4321/api/health
```
Если пусто — сервер заявок упал, смотри вывод в окне терминала.

**Ошибка `IP_SALT`** — значит `.env` остался с дефолтной солью. Скрипт её меняет сам, но если
`.env` уже существовал раньше, проверь руками: `grep IP_SALT .env`.

**`ExperimentalWarning: SQLite`** — это нормально. `node:sqlite` в 22-й помечен экспериментальным,
но работает стабильно. На данные не влияет.

**Всё сломалось, хочу с нуля** — удали `data/` и запусти снова. Демо-данные и пользователи создадутся заново.
```bash
rm -rf data && ./"Запустить всё.command"
```

## 6. Что НЕ готово и не должно удивлять

- Заявки падают в базу, но уведомлений нет: никто о них не узнаёт, пока не откроет кабинет.
- Файлы резюме не отдаются через кабинет — ручка есть в плане, не сделана.
- HH не подключён: отклики в демо-данных фейковые, «синхронизации» нет.
- Тексты из кабинета сайт пока не читает: править их можно, на страницах они не появятся.
- Публикация и «боевой режим» SEO не включены: `indexable: false`, сайт закрыт от поиска.
