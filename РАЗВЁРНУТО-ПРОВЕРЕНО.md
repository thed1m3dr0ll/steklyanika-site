# Разворачиваем на маке: пошагово и с проверками

Всё, что нужно — три команды и двойной клик. Ниже то же самое с объяснением,
чтобы при любой ошибке вы понимали, что происходит.

---

## Шаг 0. Сначала выясните, какой у вас случай

`git pull` — это и есть «скачать с GitHub», но работает он только в папке, которая уже
связана с репозиторием. Проверьте одной командой:

```bash
cd "/Users/skatinov/Downloads/Сайт Стекляника 17"
git remote -v
```

**Вариант А.** Вывелось `origin  https://github.com/thed1m3dr0ll/steklyanika-site.git` —
папка уже связана, идите к шагу 1, `git pull` подтянет мои изменения.

**Вариант Б.** Ошибка `not a git repository` — папка к репозиторию не привязана.
Тогда `pull` ничего не скачает, потому что неоткуда. Скачайте заново (шаг 0-Б).

## Шаг 0-Б. Скачать репозиторий в новую папку

Только для варианта Б. Старую папку не удаляйте — там могут быть правки, которых нет на GitHub.

```bash
cd ~/Downloads
git clone https://github.com/thed1m3dr0ll/steklyanika-site.git "Сайт Стекляника 17 - new"
cd "Сайт Стекляника 17 - new"

# macOS вешает карантин на скачанные файлы, из-за него лаунчер может не открыться.
# Снимаем только с него, всю папку не трогаем
xattr -d com.apple.quarantine "Запустить всё.command" 2>/dev/null
chmod +x "Запустить всё.command"

ls    # убедитесь, что видите server/, site/, Запустить всё.command
```

Если предложит логин и пароль — на GitHub пароль не подойдёт. Используйте токен
из настроек, как делали раньше. Для публичного репозитория клонирование
по HTTPS проходит и без авторизации.

Дальше сразу к шагу 2.

## Шаг 2. Новая зависимость

В `package.json` добавился `@astrojs/sitemap` (карта сайта). Установите:

## Шаг 3. Запуск

Двойной клик по **`Запустить всё.command`** в корне проекта — самый простой путь, ничего печатать не надо.

Если запускаете из терминала, имя надо **взять в кавычки**:

```bash
./"Запустить всё.command"
```

Почему: в имени есть пробел. Без кавычек bash читает его как разделитель и ищет файл с именем `./Запустить` — отсюда `No such file or directory`, хотя файл лежит на месте. Терминал умеет добивать имена по Tab, кавычки при этом подставляет сам — проще всего набрать `./За` и нажать Tab.

Если macOS скажет, что файл не исполняемый:

```bash
chmod +x "Запустить всё.command" && ./"Запустить всё.command"
```

Скрипт сделает сам:

1. проверит Node 22+ (и подскажет, если старее);
2. создаст `.env` со **случайной** солью для хеша IP;
3. поставит зависимости, если их нет;
4. заведёт трёх пользователей;
5. зальёт демо-данные (6 заявок, 3 вакансии, 3 отклика, 4 текста);
6. поднимет сервер заявок и сайт;
7. **сам откроет браузер** на кабинете.

Через ~6 секунд откроется:

```
http://localhost:4321/admin/cabinet/
```

## Что смотреть в первую очередь

**1. Заявки** — 6 демо-заявок. Проверьте фильтры по статусу и форму, поищите «Ирина».

**2. Форма на сайте** — откройте `http://localhost:4321/`, нажмите кнопку заявки,
отправьте. Вернитесь в кабинет, обновите — заявка появилась. Это настоящий путь
от формы до базы, а не заглушка.

**3. Резюме** — там же в форме есть вложение. Загрузите любой PDF и попробуйте
переименовать `.exe` в `.pdf` — сервер отобьёт по содержимому файла.

**4. Тексты** — четыре записи, у двух статус «черновик». Нажмите «Опубликовать» у черновика.

**5. Медиа** — загрузите фото. Без подписи (alt) не пустит — это требование SEO, а не придирка.

**6. Кабинет в коде** — откройте `site/src/pages/admin/cabinet.astro`. В начале файла карта:
панели, стили, скрипт — по номерам строк.

## Если что-то не так

**«Порт 4321 занят»**

```bash
cd site && npx astro dev stop && cd ..
```

**Кабинет пишет «Сервер не отвечает»** — не поднялся API. Проверьте:

```bash
curl localhost:4321/api/health
```

Должно быть `{"ok":true,"leads":6}`. Если пусто — смотрите вывод в окне терминала,
там будет стек ошибки.

**`Cannot find package '@astrojs/sitemap'`** — не выполнили шаг 2.

**`ExperimentalWarning: SQLite`** — нормально, это встроенный модуль Node 22.
На данные не влияет, в проде то же самое.

**Хочу с нуля**

```bash
rm -rf data && ./"Запустить всё.command"
```

Демо-данные и пользователи создадутся заново. `data/` в git не попадает, так что
это безопасно.

## Что честно не работает

Не удивляйтесь, если увидите:

- **Уведомлений о заявках нет.** Заявка падает в базу, но письмо или телеграм не приходит.
- **HH не подключён.** Нужны ключи приложения с dev.hh.ru. Код готов, статус покажет «ключи не заданы».
- **Тексты из кабинета сайт не читает.** Править можно, на страницах не появится — это следующий шаг.
- **Метрика пустая.** Нет токена, статистика вернёт заглушку.
- **Сайт закрыт от поиска.** `indexable: false` — для запуска переключить в `src/data/site.ts`.

## Что приходит с GitHub, а что создаётся на месте

Полезно понимать, чтобы не искать пропавшее.

| Приходит из GitHub | Создаётся локально при запуске |
|---|---|
| Код сайта, компоненты, стили | `site/node_modules/` — зависимости (npm install) |
| Сервер заявок и админки | `data/steklyanika.db` — база заявок |
| Документация и инструкции | `data/uploads/` — файлы резюме |
| Картинки и контент объектов | `data/media/` — медиатека |
| Конфиг `.env.example` | `.env` — ваш конфиг со случайной солью |

**Baза и загруженные файлы в GitHub не попадают намеренно.** Это персональные данные
(заявки, резюме) — им не место в публичном репозитории. Поэтому `data/` в `.gitignore`,
и на новой машине база всегда пустая. Демо-данные создаёт лаунчер.
