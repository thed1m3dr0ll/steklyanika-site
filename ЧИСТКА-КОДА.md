## Что исправил в этот заход

### 1. Дубли в серверном коде (главное)

Три функции были скопированы в `index.mjs` и `admin.mjs`:

- `readJson` — 2 копии
- `readMultipart` — 2 копии (65 строк каждая!)
- `json` — 2 копии

Две копии multipart-парсера — это не «некрасиво», это будущий баг: правишь в одном месте,
забываешь в другом, и загрузка файла разваливается только в админке, а заявки работают.
Такие баги ищутся часами.

Вынесено в `server/http.mjs`. Теперь одна реализация, один лимит тела, одно место для правки.

**Строк стало 1302 вместо 1336** — минус 34, при том что функциональность выросла.

### 2. Согласие на cookie не уходило на сервер

`src/scripts/cookies.ts`, функция `sendConsentRecord()` — там стояла заглушка с `TODO`
и комментарий «пока сервера нет». Сервер появился, а заглушка осталась.

По 152-ФЗ запись в localStorage ничего не доказывает: посетитель может её удалить или
подправить через devtools. Теперь запись уходит на `POST /api/consent` с `keepalive: true`.

`keepalive` тут не украшение: человек ставит галочку и сразу закрывает вкладку. Без него
браузер прибивает запрос вместе со страницей, и согласие теряется.

Проверил: `POST /api/consent` → 200, в таблице `consents` запись появилась.

## Что нашёл, но НЕ стал править

Самый большой файл в проекте. Это страница «О нас» с несколькими секциями в одном файле.
Разбить на компоненты можно, но:

- она работает и выглядит как надо;
- риск сломать вёрстку выше пользы;
- у вас нет тестов, а значит любая правка проверяется глазами в браузере.

**Моя рекомендация:** не трогать до появления визуальных регресс-тестов или хотя бы
скриншот-сравнения. Иначе рефакторинг ради рефакторинга.

### `: any` в кабинете — 6 штук

`cabinet.astro` типизирует ответы API как `any`. Правильно было бы описать интерфейсы:

```ts
interface Lead { id: string; name: string; contact: string; status: string; created_at: string }
```

**Почему не сделал:** кабинет — внутренний инструмент, данные приходят с нашего же сервера.
Польза от типов там есть, но не критичная. Если будем развивать кабинет — сделаем, это полчаса.

## Как проверять такие вещи самому

```bash
cd site

npx tsc --noEmit

# 2. сборка
npm run build

# 3. дубли функций в сервере
grep -c "function readMultipart\|function readJson" ../server/*.mjs

# 4. мусор в коде
grep -rn "console.log\|TODO\|FIXME" src/ --include='*.ts' --include='*.astro'

# 5. самые большие файлы — там обычно и прячется беспорядок
wc -l src/components/*.astro src/pages/*.astro | sort -rn | head
```
